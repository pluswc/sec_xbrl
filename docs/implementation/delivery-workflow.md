# 공통 마일스톤 전달 운영 절차

이 문서는 M0 이후 모든 마일스톤에 적용하는 범용 전달 절차다. 요구사항 판단, 구현, 독립 검증, PR·CI·병합 판단을 분리하여 공유 작업 트리의 동시 수정과 자기 검증 누락을 방지한다.

## 1. 역할 분리

### 총괄 세션

총괄 세션은 작업의 판단과 인계를 담당한다.

- 요구사항, 범위, 가정, 수락 기준을 확정한다.
- 구현 세션에 변경 범위와 완료 기준을 위임한다.
- 독립 검증 결과를 수락 기준과 대조한다.
- PR 생성·수정 여부, CI 결과 수용, 병합 준비 여부를 최종 판단한다.

총괄 세션은 구현 작업 트리의 소스 파일을 직접 수정하지 않는다. 긴급 수정이 필요하면 구현 세션에 반환한다.

### 구현 세션

구현 세션은 해당 마일스톤 브랜치의 **유일한 소스 수정자**다.

- 합의된 수락 기준을 만족하는 최소 수직 슬라이스를 구현한다.
- 관련 문서와 테스트를 같은 변경에 포함한다.
- 자체 단위·통합·정적 검사를 실행한다.
- 변경을 하나 이상의 의미 있는 커밋으로 남긴다.
- 검증 시작 전에 브랜치를 push하고 동결한다.

### 독립 검증 세션

독립 검증 세션은 수정 권한을 행사하지 않는 읽기 전용 검토자다.

- 요구사항과 수락 기준을 구현 결과와 독립적으로 대조한다.
- 관련 테스트와 필요한 전체 테스트를 재실행한다.
- 무결성, 경계 조건, 문서·계약 일치 여부를 확인한다.
- 결과를 `PASS` 또는 `FAIL`로 명확히 보고한다.

독립 검증 세션은 소스·테스트·문서를 직접 수정하거나 커밋하지 않는다.

## 2. 공유 작업 트리와 브랜치 동결

공유 작업 트리를 수정하는 세션은 언제나 하나뿐이어야 한다. 구현 도중 총괄 및 독립 검증 세션은 읽기·분석·테스트 실행만 수행하며 파일을 변경하지 않는다.

구현 세션은 기능과 자체 검증을 마친 뒤 커밋하고 원격 브랜치에 push한다. 이 커밋을 검증 대상 후보로 지정한 시점부터 브랜치는 동결한다. 독립 검증은 반드시 동결된 commit SHA를 기준으로 수행한다. 동결 이후 수정이 생기면 새 커밋을 push한 뒤, 그 새 SHA를 기준으로 독립 검증을 처음부터 다시 수행한다.

## 3. 발견 사항의 반환

독립 검증에서 결함, 계약 불일치, 누락된 테스트, 문서 불명확성이 발견되면 다음을 포함해 구현 세션으로 반환한다.

- 심각도와 재현 절차
- 기대 결과와 실제 결과
- 관련 수락 기준 또는 계약 문서 위치
- 재실행이 필요한 검증 명령

검증자는 해결책을 제안할 수 있지만 직접 수정하지 않는다. 구현 세션이 수정·테스트·커밋을 완료하면 브랜치를 다시 동결하고 독립 검증을 재실행한다.

## 4. 표준 절차

1. 총괄 세션이 요구사항·수락 기준·가정·역할을 확정한다.
2. 구현 세션만 작업 트리를 수정하고 자체 테스트 후 커밋·push한다.
3. 구현 커밋 SHA를 지정하여 브랜치를 동결한다.
4. 독립 검증 세션이 수정 없이 수락 기준 대조와 테스트 재실행을 수행하고 `PASS`/`FAIL`을 보고한다.
5. `FAIL`이면 발견 사항을 구현 세션에 반환하고 2단계부터 반복한다.
6. `PASS`이면 총괄 세션이 PR, CI, 병합 준비 여부를 판단한다.

## 5. PR 작성 규칙

- PR 제목과 본문은 한국어와 영어를 모두 제공한다. 제목은 두 언어를 함께 쓰거나, 본문 첫 부분에 두 언어 요약을 분명히 둔다.
- 본문에는 범위, 핵심 변경, 수락 기준 대응, 검증 명령과 결과, 알려진 제약을 포함한다.
- GitHub CLI로 본문을 만들거나 갱신할 때는 실제 줄바꿈을 사용한다. 본문 파일 또는 ANSI-C quoting을 사용하고, 리터럴 `\n` 문자열을 전달하지 않는다. GitHub는 리터럴 `\n`을 줄바꿈이 아닌 텍스트로 표시한다.
- PR 생성·갱신 후에는 GitHub에서 렌더링된 제목과 본문을 읽어 형식과 줄바꿈을 확인한다.

## 6. 적용 범위

이 절차는 M0 이후의 코드, 계약, 아키텍처, 테스트, 마이그레이션 문서 변경에 적용한다. 단순 읽기 전용 조사나 사용자에게만 제공하는 설명은 역할 분리가 필요 없을 수 있지만, PR을 만들 변경에는 이 절차를 따른다.

# 스크리닝 조건과 결과의 근접 워크시트

2026-11-12 사용자/리드 승인. 기준 `3bb879e50b`의 재무 워크벤치를 유지한다.
투자자가 정확한 조건을 빠르게 입력한 뒤 결과 행을 비교하도록 기존 ivory·ink·
blue와 native controls, 4px 간격 체계를 사용한다.

감사에서 조건 행의 2fr 지표/1fr 기준값이 큰 화면에서 약 956/478px로 늘고,
도움말 아래쪽 정렬 때문에 입력 시작점이 어긋남을 확인했다. 조건 이름·저장·
빈도/기간이 의미 구분 없이 같은 grid에 있었으며 범위/검색도 과도하게 늘었다.
결과 표는 intrinsic 엔진이 있으나 회사별 최신의 실제 기간 열이 숫자 열로
오분류되어 116px nowrap에 들어가 옆 금액·관심상태를 침범했다.

- 조건 편집은 약 1000px에 제한하고 이름·선택적 저장 조건·분석 기간을 구분한다.
  조건 패널도 약 1064px로 제한하고 desktop의 기간·기업 범위는 나란히 둔다.
  기존 DOM 노드를 이동해 ID·핸들러·조건 직렬화를 보존한다. 반복 카드 대신
  구분선과 범주를 사용한다. 지표/연산자/기준값의 위쪽 입력선을 맞춘다.
- 기업 범위·카테고리·검색은 필요한 폭을 갖는다. 모든 기업/업종/선택 모드와
  저장 버전 불러오기, 연간/분기/최신/고정 기간 동작을 유지한다.
- 결과는 기업 240px, 상태/관심 120px, 실제 기간 약 220px, 지표 약 140px로
  내용 폭을 유지하고 많은 열과 모바일은 내부 스크롤을 사용한다. 최신 결과의
  실제 기간만 명시적인 period 역할로 고치며 고정 기간과 숨은 기업 열은 유지한다.
  원래 줄바꿈과 날짜 토큰을 보존해 금액을 침범하지 않도록 한다.
- 헤더는 기존 유효한 약칭만 사용하고 전체 이름·단위를 제공한다. 값은 전체
  지표명·표시값/단위·공표 원값·기존 실제 기간, 누락은 사유를 native title/접근성
  이름으로 제공한다. 새 전역 tooltip, 정렬/판정/financial 계산을 만들지 않는다.
- 시험 결과와 편집 중 조건의 차이는 기존 amber 안내로 유지한다. 판정 필터·
  기업 선택·근거 상세·다운로드·조건/결과 저장·재열기는 기존 경로를 사용한다.

허용은 app.js/app.css, 관련 tests/screening Node 검사, 이 계약과 planning index다.
backend ui.py·API·생산기·자료·artifact·저널·main·운영 프로세스는 수정하지 않는다.
